# stroll

シードから生成される、空から自然を見つけて降り、歩ける世界。目的も、期限もない。

URL を共有すると、同じ地形を友達と一緒に歩ける。

```
https://stroll.hochu.workers.dev/#k7p2mq9x
                                 ^^^^^^^^ 合言葉。英数字 8 文字
```

公開版: https://stroll.hochu.workers.dev

## 歩き方

キーボード: `WASD` 移動 / `Shift` 走る・高速飛行 / `Space` 跳ぶ・上昇 /
`C` 下降 / `F` 飛ぶ・降りる / `R` 自動飛行 / `M` 消音 / `Esc` 一時停止。
飛行中は通常 78m/s、高速 112m/s。自動飛行は高度を保って前へ進み、
視点だけを自由に動かせる。

スマホ: 左半分をなぞって移動し、外周まで倒すと加速。右半分をなぞって見回す。
右下の三角で飛ぶ・降りる、`AUTO` で自動飛行、上矢印で跳ぶ・上昇する。
縦画面では見える範囲を少し広げ、対応ブラウザでは全画面表示になる。

同じ世界へ戻ると、7日以内の最後の位置から続けられる。開始地点から入り直すこともできる。

同じ合言葉なら同じ地形。URL を送れば友達と同じ世界を一緒に歩ける。

## 動かす

```bash
npm install
npm run dev      # http://localhost:5173（LAN 公開。スマホからも見られる）
npm run relay    # 別のターミナルで。マルチプレイの中継サーバ
npm run ci       # 型・ビルド・テスト（push 前に通す）
npm run deploy   # 手元から Cloudflare へ出す（通常は不要。下記 CD が出す）
```

`npm run relay` を動かさなくても 1 人で歩ける。

## デプロイ

**main に入ったものが、検証を通ったときだけ自動で本番へ出る。**

```
PR           → 型・ビルド・テスト（.github/workflows/ci.yml）
main へ push → 同じ検証 → 通ったときだけ Cloudflare へ（deploy.yml）
```

Cloudflare 側の Git 連携は**使わない**。あれは検証のゲートが無く、CI が落ちても
本番に出てしまうため。デプロイの条件と環境はワークフローに書いてある。

fork する場合は Secrets に `CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID` を
登録し、`server/wrangler.jsonc` の `name` を自分のものに変える。

## 設計の芯

**外部アセットを一切使わない。** 地形も、木も、音も、その場で計算して作る。
だから合言葉（`#...`）さえ同じなら、誰のブラウザでも寸分違わず同じ世界が
再現される。サーバは地形を送らない。送るのは座標だけ。

この 1 点が「無限に広い世界」と「URL を渡すだけで一緒に歩ける」を同時に成立させている。

**洞窟や穴は作らない。** 地形は高さマップなので、原理的に閉じた空間ができない。
怖くない、開けた場所だけの世界にするための選択。

## 世界の三層

歩くと景色が変わるのは、3 つの層が重なっているから。すべて `(x,z)` とシードの純粋関数。

1. **標高** — 平原・丘・山・台地・谷・島。ノイズを足すのではなく、
   3 つのパラメータ（大陸度・侵食度・ねじれ）を**折れ点を持つスプライン**に通す。
   平らな区間が平原と台地に、急な区間が崖と海岸線になる。
2. **気候**（気温 × 湿り気）— 砂漠・草原・森・密林・寒帯・雪。
   **どちらも地形から決まる。** 気温は標高で下がり、湿り気は**雨陰**で決まる ──
   風上に自分より高い山があると乾く。だから山を越えると景色が変わる。
3. **宝物** — まれに現れ、気候を無視して上書きするレア区画。秋・桜・青い草原など。

## 拡張するときの判断基準

> **`(x, z)` とシードだけから、純粋な関数として計算できるか？**

これを満たす限り、無限生成も URL 共有も壊れない。

| やりたいこと | 難易度 | どこを触るか |
|---|---|---|
| 新しい気候帯 | 易 | `world/surfaceShade.ts` の色と `world/vegetationSpecs.ts` の植生条件 |
| 新しい宝物（色の森・草原） | 易 | `world/special.ts` に `forest()`/`meadow()` を 1 行 |
| 新しい木 | 易 | `vegetationKinds.ts` に KIND、`render/treeCatalog.ts` に形、`world/vegetationSpecs.ts` に配置 |
| 新しい地形の種類（盆地・砂丘） | 中 | `world/landform.ts` に 1 行、`world/terrainShape.ts` に高さの式を 1 つ |
| 村・遺跡 | 中 | `terrainShape.heightAt()` が村の中心付近で平坦な台地へブレンドする |
| 内陸の湖 | 中 | `world/lake.ts` に 1 行。水面は区画ごとに 1 つの定数なので必ず水平になる |
| 水のある川 | 難 | 水面が流れに沿って下がる必要がある。**流れの計算ではなく水面の形が壁**（下記） |

最密チャンクは標高だけで `(96+3)² = 9,801` 点を引き、さらに湖・植生の判定が乗る。
層を足すほど生成が重くなるので、その予算内で考えること。

生成コードは、外向きには `world/terrain.ts` の `Terrain` だけを入口にし、内部を分けている。

- `world/terrainShape.ts` — 大陸度・侵食度・尾根、丘陵・山塊・台地・涸れ谷
- `world/climate.ts` — 気温・雨陰を含む湿り気・森のまとまり
- `world/surfaceShade.ts` — 気候帯・砂浜・岩・雪の地面色
- `world/vegetationSpecs.ts` — 気候ごとの植生条件
- `world/scatter.ts` — 候補格子、遅延する傾き判定、配置データ化
- `world/spawn.ts` — 湖・崖・木立を避けた開始地点の選定
- `render/treeCatalog.ts` — 本番と見本帳が共有する木の一覧

### 湖はできて、川はできない理由

「水はどちらへ流れるかという大域情報が要る」と考えていたが、それは正しくなかった。
Minecraft も水の流れを計算していない（ノイズがゼロを横切る線を谷にしているだけ）。

**壁は水面の"形"にある。** 水面は「その場所の水面の高さ」を返す純粋関数でなければ
ならない。

- **湖は水面が区画ごとに 1 つの定数**なので、定義上かならず水平になる。
  宝物・台地と同じ「升目で抽選して円形の区画を作る」機構がそのまま使える
- **川は水面が流れに沿って下がる必要がある。** だが地形は排水路ではないので、
  川筋に沿った高さが上下する（実測で ±60m の間に 7.0m）。中心線に射影しても直らない

水を入れるために地面を海面下まで彫る手もあるが、深く彫るほど低地が水没して
海岸がリアス式になる（水際の交差が 2.5 → 3.5 回/km）。
**「水が繋がる」と「海岸が綺麗」が原理的に両立しない。**
いまは 9m の涸れ谷として、谷の骨格だけ入れてある。

## 構成

依存は一方向に流れる（循環なし）。逆向きの import を足さないこと。
`main.ts` だけが全部を知り、組み立てる。

```
core ← world ← player ← ui
core ← world ← render → (net, player)
core ← audio
net（何にも依存しない）      shared（合言葉の決まり。client と server が使う）
```

- `render` は世界・入力・通信を束ねて描く（一番多くを知る層）。
- `ui` は入力方式の都合で `player` に触れる（`touch.ts` が操作を渡す）。

| ディレクトリ | 役割 |
|---|---|
| `core/` | シード付き乱数とハッシュ |
| `shared/` | クライアントとサーバで共有する決まり（合言葉の検証） |
| `world/` | 地形・気候・宝物の定義、チャンクのメッシュ化、植生の配置。描画を知らない |
| `render/` | 空・水・植生・アバター・チャンクの出し入れ |
| `player/` | 入力と移動 |
| `audio/` | 足音と環境音。すべて合成 |
| `net/` | 部屋への接続 |
| `ui/` | 開始画面・合言葉入力・タッチ操作 |
| `server/` | Cloudflare Worker + Durable Object の中継 |

## 触るときの注意（型検査を通るのに壊れる場所）

- `terrain.heightOnGrid()` と `chunk.buildChunkArrays()` は
  **同じ三角形の切り方**をしている前提。片方だけ変えると足元が地面から浮く。
- `chunk.ts` の `LOD_STEPS` と `LOD_RINGS` は同じ長さであること（起動時に検査している）。
- Worker の生成は `new URL('../world/worker.ts', import.meta.url)` という
  **文字列リテラル**。ファイルを移動しても型検査では気づけない。
- `world/special.ts` の宝物抽選はシードを混ぜる。忘れると全世界で宝物が同じ位置に出る。
- 非インデックスのジオメトリを頂点番号で変形しない（同じ角が裂ける）。座標から乱数を引く。
- 生成コードを整理するだけなら `test/world-generation.test.mjs` の固定値を変えない。
  意図して景色を変えるときだけ、画面と統計を確認してスナップショットを更新する。
